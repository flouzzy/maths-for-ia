## 1. Objectifs

### 1.1 Objectif Mathématique

Ce TP vise à explorer le concept de **problèmes bien posés** et **mal posés** en analyse numérique, tel que défini par Jacques Hadamard. Un problème est dit bien posé si :
1.  Une solution existe.
2.  La solution est unique.
3.  La solution dépend continûment des données initiales (stabilité).

Nous nous concentrerons particulièrement sur le troisième critère, la **stabilité**, en étudiant l'impact de petites perturbations des données sur la solution d'un système linéaire. Ceci nous amènera à comprendre le rôle du **nombre de conditionnement** d'une matrice, une mesure de la sensibilité de la solution aux erreurs dans les données ou aux erreurs d'arrondi.

## 2. Introduction au Conditionnement

En algèbre linéaire numérique, la résolution d'un système d'équations `Ax = b` est une opération fondamentale. Cependant, la précision de la solution `x` peut être fortement affectée par de petites erreurs (erreurs de mesure, erreurs d'arrondi) dans la matrice `A` ou le vecteur `b`. Le nombre de conditionnement d'une matrice `A`, noté `cond(A)`, quantifie cette sensibilité.

Pour un système linéaire `Ax = b`, si nous introduisons une petite perturbation `δb` dans `b`, nous obtenons un nouveau système `Ax' = b + δb`, dont la solution `x'` sera légèrement différente de `x`. Le rapport entre l'erreur relative de la solution (`||x - x'|| / ||x||`) et l'erreur relative des données (`||b - (b + δb)|| / ||b||`) est borné par le nombre de conditionnement :

`||x - x'|| / ||x|| <= cond(A) * (||b - (b + δb)|| / ||b||)`

Une matrice avec un `cond(A)` élevé (par exemple, > 1000) est considérée comme **mal conditionnée**, signifiant que de petites erreurs dans `b` peuvent entraîner de très grandes erreurs dans `x`. Inversement, une matrice avec un `cond(A)` faible (par exemple, < 100) est **bien conditionnée**, garantissant une solution stable.

Pour ce TP, nous utiliserons la bibliothèque `numpy` pour les opérations d'algèbre linéaire (résolution de systèmes, calcul de normes, calcul du nombre de conditionnement). L'objectif n'est pas de réimplémenter ces algorithmes complexes depuis zéro, mais d'utiliser ces outils standards pour observer et comprendre le phénomène de conditionnement.

## 3. Implémentation en Python

```python
import numpy as np

# --- Fonctions utilitaires ---

def calculate_relative_error(original_vector, perturbed_vector):
    """
    Calcule l'erreur relative entre deux vecteurs.
    Utilise la norme euclidienne (L2).

    Args:
        original_vector (np.array): Le vecteur original.
        perturbed_vector (np.array): Le vecteur perturbé.

    Returns:
        float: L'erreur relative.
    """
    # np.linalg.norm calcule la norme L2 par defaut pour les vecteurs
    return np.linalg.norm(original_vector - perturbed_vector) / np.linalg.norm(original_vector)

def hilbert_matrix(n):
    """
    Génère une matrice de Hilbert de taille n x n.
    Les matrices de Hilbert sont célèbres pour être mal conditionnées.

    Args:
        n (int): La dimension de la matrice.

    Returns:
        np.array: La matrice de Hilbert.
    """
    H = np.zeros((n, n))
    for i in range(n):
        for j in range(n):
            H[i, j] = 1.0 / (i + j + 1)
    return H

# --- Section 1 : Problème Bien Posé ---
print("--- Section 1 : Étude d'un Problème Bien Posé ---")

# 1.1 Définition d'une matrice bien conditionnée
# Choisissons une matrice dont les valeurs propres sont bien espacées
A_bien_conditionnee = np.array([[2, 1],
                                [1, 3]])

# Définissons une "vraie" solution x pour calculer b
x_vrai_bien = np.array([1.0, 2.0])
b_bien = A_bien_conditionnee @ x_vrai_bien

print(f"Matrice A (bien conditionnée):\n{A_bien_conditionnee}")
print(f"Vecteur b (données initiales):\n{b_bien}")
print(f"Vraie solution x:\n{x_vrai_bien}")

# 1.2 Calcul du nombre de conditionnement
cond_A_bien = np.linalg.cond(A_bien_conditionnee)
print(f"\nNombre de conditionnement de A_bien_conditionnee : {cond_A_bien:.2f}")

# Assertion : Vérifier que le nombre de conditionnement est faible
assert cond_A_bien < 100, f"Le nombre de conditionnement de A_bien_conditionnee devrait être faible (actuel: {cond_A_bien:.2f})"
print("ASSERTION OK : Le nombre de conditionnement est faible.")

# 1.3 Introduction de bruit dans les données
# Ajoutons une petite perturbation au vecteur b
epsilon_b = 1e-4  # Magnitude du bruit
# Générons un vecteur de bruit aléatoire de même dimension que b
bruit_b = np.random.rand(len(b_bien)) * epsilon_b
b_bien_bruite = b_bien + bruit_b

print(f"\nVecteur b bruité (b + bruit):\n{b_bien_bruite}")

# Calcul de l'erreur relative dans les données (b)
erreur_relative_b_bien = calculate_relative_error(b_bien, b_bien_bruite)
print(f"Erreur relative introduite dans b : {erreur_relative_b_bien:.6e}")

# 1.4 Résolution des systèmes et comparaison des solutions
x_resolu_bien = np.linalg.solve(A_bien_conditionnee, b_bien)
x_resolu_bien_bruite = np.linalg.solve(A_bien_conditionnee, b_bien_bruite)

print(f"\nSolution x_résolu (sans bruit) :\n{x_resolu_bien}")
print(f"Solution x_résolu_bruité (avec bruit) :\n{x_resolu_bien_bruite}")

# Calcul de l'erreur relative dans la solution (x)
erreur_relative_x_bien = calculate_relative_error(x_vrai_bien, x_resolu_bien_bruite)
print(f"Erreur relative dans la solution x : {erreur_relative_x_bien:.6e}")

# 1.5 Analyse et Assertions
# Pour un problème bien posé, l'erreur relative dans la solution ne devrait pas être
# significativement plus grande que l'erreur relative dans les données,
# multipliée par le nombre de conditionnement (qui est faible ici).
# La stabilité est bonne : petite perturbation dans b => petite perturbation dans x.

# La borne supérieure est cond(A) * erreur_relative_b.
# On s'attend à ce que l'erreur_relative_x soit du même ordre de grandeur ou légèrement supérieure
# à erreur_relative_b, mais pas amplifiée de manière catastrophique.
assert erreur_relative_x_bien <= cond_A_bien * erreur_relative_b_bien * 1.5, \
    f"Pour une matrice bien conditionnée, l'erreur relative de x ({erreur_relative_x_bien:.6e}) " \
    f"devrait être <= cond(A) * erreur_relative_b ({cond_A_bien * erreur_relative_b_bien:.6e})"
print("ASSERTION OK : L'erreur relative dans la solution est proportionnelle à l'erreur des données et au conditionnement (faible amplification).")

print("\nConclusion Section 1 : Le problème est bien posé, la solution est stable face aux perturbations des données.")


# --- Section 2 : Problème Mal Posé ---
print("\n" + "="*70)
print("--- Section 2 : Étude d'un Problème Mal Posé ---")

# 2.1 Définition d'une matrice mal conditionnée
# Utilisons une matrice de Hilbert de taille 3x3
A_mal_conditionnee = hilbert_matrix(3)

# Définissons une "vraie" solution x pour calculer b
x_vrai_mal = np.array([1.0, 1.0, 1.0])
b_mal = A_mal_conditionnee @ x_vrai_mal

print(f"Matrice A (mal conditionnée, Hilbert 3x3):\n{A_mal_conditionnee}")
print(f"Vecteur b (données initiales):\n{b_mal}")
print(f"Vraie solution x:\n{x_vrai_mal}")


# 2.2 Calcul du nombre de conditionnement
cond_A_mal = np.linalg.cond(A_mal_conditionnee)
print(f"\nNombre de conditionnement de A_mal_conditionnee : {cond_A_mal:.2f}")

# Assertion : Vérifier que le nombre de conditionnement est élevé
assert cond_A_mal > 1000, f"Le nombre de conditionnement de A_mal_conditionnee devrait être élevé (actuel: {cond_A_mal:.2f})"
print("ASSERTION OK : Le nombre de conditionnement est élevé.")

# 2.3 Introduction de bruit dans les données
# Ajoutons une petite perturbation au vecteur b, de même magnitude que précédemment
epsilon_b_mal = 1e-4
bruit_b_mal = np.random.rand(len(b_mal)) * epsilon_b_mal
b_mal_bruite = b_mal + bruit_b_mal

print(f"\nVecteur b bruité (b + bruit):\n{b_mal_bruite}")

# Calcul de l'erreur relative dans les données (b)
erreur_relative_b_mal = calculate_relative_error(b_mal, b_mal_bruite)
print(f"Erreur relative introduite dans b : {erreur_relative_b_mal:.6e}")

# 2.4 Résolution des systèmes et comparaison des solutions
x_resolu_mal = np.linalg.solve(A_mal_conditionnee, b_mal)
x_resolu_mal_bruite = np.linalg.solve(A_mal_conditionnee, b_mal_bruite)

print(f"\nSolution x_résolu (sans bruit) :\n{x_resolu_mal}")
print(f"Solution x_résolu_bruité (avec bruit) :\n{x_resolu_mal_bruite}")

# Calcul de l'erreur relative dans la solution (x)
erreur_relative_x_mal = calculate_relative_error(x_vrai_mal, x_resolu_mal_bruite)
print(f"Erreur relative dans la solution x : {erreur_relative_x_mal:.6e}")

# 2.5 Analyse et Assertions
# Pour un problème mal posé, on s'attend à ce que l'erreur relative dans la solution
# soit considérablement amplifiée par rapport à l'erreur relative dans les données,
# reflétant le nombre de conditionnement élevé.
# La stabilité est mauvaise : petite perturbation dans b => grande perturbation dans x.

# On s'attend à ce que erreur_relative_x_mal >> erreur_relative_b_mal
# et que le rapport erreur_relative_x_mal / erreur_relative_b_mal soit de l'ordre de cond(A_mal).
assert erreur_relative_x_mal > erreur_relative_b_mal * 100, \
    f"Pour une matrice mal conditionnée, l'erreur relative de x ({erreur_relative_x_mal:.6e}) " \
    f"devrait être significativement plus grande que l'erreur relative de b ({erreur_relative_b_mal:.6e})."
assert erreur_relative_x_mal > cond_A_mal * erreur_relative_b_mal / 100, \
    f"L'erreur relative de x ({erreur_relative_x_mal:.6e}) n'est pas suffisamment amplifiée par cond(A)."
print("ASSERTION OK : L'erreur relative dans la solution est fortement amplifiée, indiquant une instabilité.")

print("\nConclusion Section 2 : Le problème est mal posé, la solution est instable face aux perturbations des données.")
print("\n" + "="*70)
print("FIN DU TP 04 : Les problèmes bien/mal posés et le conditionnement de matrices ont été explorés avec succès.")
