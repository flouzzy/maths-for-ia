## Introduction : Problèmes Bien Posés et Mal Posés

Un problème mathématique est considéré comme **bien posé** (au sens d'Hadamard) s'il satisfait trois critères fondamentaux :
1.  **Existence** : Une solution au problème existe.
2.  **Unicité** : La solution est unique.
3.  **Stabilité** : La solution dépend continûment des données initiales. Cela signifie que de petites modifications ou erreurs dans les données d'entrée n'entraînent que de petites modifications dans la solution.

Si l'une de ces conditions n'est pas remplie, le problème est dit **mal posé**. En calcul numérique, la troisième condition (stabilité) est souvent la plus critique. Un problème instable, où de minuscules erreurs de mesure ou d'arrondi peuvent radicalement changer la solution, est numériquement très difficile à résoudre de manière fiable.

Le **conditionnement d'une matrice** est une mesure clé de cette stabilité. Pour un système linéaire $Ax=b$, le nombre de conditionnement de la matrice $A$ (noté $\kappa(A)$ ou `cond(A)`) est un indicateur de la sensibilité du système aux erreurs. Une valeur élevée de $\kappa(A)$ signifie que le problème est mal conditionné, et qu'une petite erreur sur $b$ peut se traduire par une grande erreur sur $x$.

La **régularisation de Tikhonov** est une technique couramment utilisée pour transformer un problème mal posé en un problème bien posé, plus stable numériquement. Elle est particulièrement utile pour les problèmes de moindres carrés en ajoutant une pénalité qui favorise des solutions "raisonnables" ou "lisses", souvent en limitant leur norme.

## Partie 1 : Génération et analyse d'une matrice mal conditionnée

Nous allons utiliser la **matrice de Hilbert** comme exemple par excellence de matrice mal conditionnée. Une matrice de Hilbert $H$ de taille $n \times n$ est définie par ses éléments $H_{ij} = \frac{1}{i+j-1}$ pour $i, j = 1, \dots, n$ (ou $H_{ij} = \frac{1}{i+j+1}$ si les indices commencent à 0).

Plus la taille $n$ de la matrice de Hilbert augmente, plus son nombre de conditionnement croît de manière exponentielle, rendant son inversion numérique de plus en plus difficile et instable.

### Code Python

```python
import math
import collections

# La bibliothèque numpy est utilisée ici pour les opérations d'algèbre linéaire de base
# (création de matrices, multiplication, inversion, normes, résolution de systèmes).
# L'objectif est de se concentrer sur les concepts de conditionnement et de régularisation,
# et non sur la réimplémentation des primitives d'algèbre linéaire, qui sont déjà optimisées
# et stables dans numpy. L'implémentation des concepts pédagogiques restera explicite.
try:
    import numpy as np
except ImportError:
    print("Numpy n'est pas installé. Veuillez l'installer avec 'pip install numpy'")
    exit()

def creer_matrice_hilbert(n):
    """
    Crée une matrice de Hilbert de taille n x n.
    Les éléments H[i, j] sont définis comme 1 / (i + j + 1) en utilisant des indices
    basés sur 0 pour les lignes et les colonnes.

    Args:
        n (int): La dimension de la matrice (n x n).

    Returns:
        np.ndarray: La matrice de Hilbert.
    """
    matrice = np.zeros((n, n))
    for i in range(n):
        for j in range(n):
            matrice[i, j] = 1.0 / (i + j + 1.0) # Indices commencent à 0, donc +1
    return matrice

def perturber_vecteur(vecteur, magnitude_perturbation_relative):
    """
    Ajoute une petite perturbation aléatoire à un vecteur.
    La magnitude de la perturbation est relative à la norme du vecteur original.

    Args:
        vecteur (np.ndarray): Le vecteur à perturber.
        magnitude_perturbation_relative (float): La proportion de la norme du vecteur
                                                  pour la magnitude de la perturbation.

    Returns:
        np.ndarray: Le vecteur perturbé.
    """
    # Génère une perturbation aléatoire de même forme que le vecteur
    # Multiplie par la magnitude relative et la norme du vecteur pour dimensionner la perturbation
    perturbation = np.random.rand(*vecteur.shape) * magnitude_perturbation_relative * np.linalg.norm(vecteur)
    return vecteur + perturbation

def resoudre_systeme_lineaire(A, b):
    """
    Résout le système linéaire Ax = b.

    Args:
        A (np.ndarray): La matrice du système.
        b (np.ndarray): Le vecteur du côté droit.

    Returns:
        np.ndarray: Le vecteur solution x.
    """
    # np.linalg.solve est une implémentation robuste et optimisée de la résolution
    # de système linéaire qui gère bien les cas numériques tant que la matrice
    # n'est pas singulière ou trop mal conditionnée pour être inversée numériquement.
    return np.linalg.solve(A, b)

# --- Démonstration et Validation du Conditionnement ---
print("--- Démonstration du Conditionnement ---")

n_hilbert = 10 # Taille de la matrice de Hilbert
A_hilbert = creer_matrice_hilbert(n_hilbert)

# Calcul du nombre de conditionnement de la matrice de Hilbert
# np.linalg.cond calcule le nombre de conditionnement en utilisant la norme 2 par défaut,
# ce qui est une mesure standard de la sensibilité.
cond_A_hilbert = np.linalg.cond(A_hilbert)
print(f"Nombre de conditionnement de la matrice de Hilbert de taille {n_hilbert}: {cond_A_hilbert:.2e}")

# Assertion pour valider que la matrice est bien mal conditionnée pour la taille choisie.
# Un seuil courant pour considérer une matrice mal conditionnée est souvent au-delà de 1000 ou 1e4.
# Pour n=10, la matrice de Hilbert est extrêmement mal conditionnée.
assert cond_A_hilbert > 1e10, "La matrice de Hilbert n'est pas suffisamment mal conditionnée pour cette taille (n). Le test n'est pas représentatif."
print("Validation: Le nombre de conditionnement est bien élevé, confirmant une matrice mal conditionnée.")

# Créons un vecteur solution exact (x_vrai) et le vecteur b correspondant
x_vrai = np.ones(n_hilbert) # Un vecteur simple de 1 pour faciliter la compréhension
b_vrai = A_hilbert @ x_vrai # Calculons b tel que A * x_vrai = b

# Résolution du système Ax = b avec b_vrai (sans perturbation)
x_calcule = resoudre_systeme_lineaire(A_hilbert, b_vrai)

# Vérifions que la solution calculée est très proche de la solution vraie
# Utilisons la norme de la différence pour quantifier l'erreur.
diff_norm_sans_perturb = np.linalg.norm(x_calcule - x_vrai)
print(f"Différence entre x_calcule et x_vrai (norme 2, sans perturbation): {diff_norm_sans_perturb:.2e}")
assert diff_norm_sans_perturb < 1e-9, "La solution calculée sans perturbation ne correspond pas à la solution vraie avec une précision suffisante."
print("Validation: La solution calculée sans perturbation est correcte et précise.")


# Testons l'impact d'une petite perturbation sur le vecteur b
magnitude_perturb_relative = 1e-7 # Une très petite perturbation relative (0.00001% de la norme de b)
b_perturbe = perturber_vecteur(b_vrai, magnitude_perturb_relative)

# Résolvons le système avec le vecteur b perturbé
x_calcule_perturbe = resoudre_systeme_lineaire(A_hilbert, b_perturbe)

# Comparons la solution perturbée à la solution vraie
diff_norm_perturb = np.linalg.norm(x_calcule_perturbe - x_vrai)
print(f"Différence entre x_calcule_perturbe et x_vrai (norme 2) pour une perturbation de b de {magnitude_perturb_relative:.1e} (relative): {diff_norm_perturb:.2e}")

# Vérifions que la perturbation a un impact significatif sur la solution.
# L'erreur relative sur x devrait être approximativement cond(A) * (erreur relative sur b).
# Si cond_A_hilbert est ~1e13 et magnitude_perturb_relative est 1e-7, l'erreur relative sur x peut être de l'ordre de 1e6.
expected_relative_error_x = cond_A_hilbert * magnitude_perturb_relative
print(f"Erreur relative attendue sur x (théorique): {expected_relative_error_x:.2e}")
actual_relative_error_x = diff_norm_perturb / np.linalg.norm(x_vrai)
print(f"Erreur relative réelle sur x: {actual_relative_error_x:.2e}")

# On s'attend à une erreur relative sur x qui est plusieurs ordres de grandeur plus grande
# que l'erreur relative sur b, à cause du mauvais conditionnement.
assert actual_relative_error_x > 1e-3, "La solution perturbée n'est pas suffisamment différente de la solution vraie pour une matrice mal conditionnée. Le problème est moins instable que prévu ou la perturbation est trop faible."
print("Validation: La perturbation de b a bien amplifié l'erreur sur x de manière significative, démontrant l'instabilité du système mal conditionné.")
print("--- Fin Démonstration du Conditionnement ---")

print("n")

## Partie 2 : Régularisation de Tikhonov

Pour un problème de moindres carrés min |Ax - b|^2, la solution classique est donnée par les équations normales : A^T A x = A^T b. Si la matrice A^T A est mal conditionnée (ce qui est souvent le cas si A elle-même est mal conditionnée ou si elle n'est pas de plein rang), cette solution est numériquement instable.

La régularisation de Tikhonov modifie le problème d'optimisation en ajoutant un terme de pénalité à la fonction objectif :
min |Ax - b|^2 + lambda^2 |Lx|^2
où L est une matrice de régularisation (souvent la matrice identité I) et lambda > 0 est le **paramètre de régularisation**.

La solution de ce problème régularisé est alors donnée par le système linéaire suivant :
(A^T A + lambda^2 L^T L) x_{lambda} = A^T b

Si nous choisissons L=I (la matrice identité), la solution analytique simplifiée est :
x_{lambda} = (A^T A + lambda^2 I)^{-1} A^T b

L'objectif est de choisir un paramètre lambda approprié. Un lambda trop petit n'apportera pas la stabilité nécessaire, laissant la solution vulnérable aux perturbations. À l'inverse, un lambda trop grand "sur-régularisera" le problème, déformant excessivement la solution et l'éloignant de la "vraie" solution sous-jacente. La sélection optimale de lambda est un sujet en soi (par exemple, via la méthode de la courbe en L).

### Code Python

```python
def tikhonov_regularization(A, b, lambda_param, L=None):
    """
    Applique la régularisation de Tikhonov pour résoudre le problème de moindres carrés Ax = b.
    L'objectif est de minimiser ||Ax - b||^2 + lambda_param^2 * ||Lx||^2.

    Args:
        A (np.ndarray): La matrice du système de moindres carrés.
        b (np.ndarray): Le vecteur des observations ou du côté droit.
        lambda_param (float): Le paramètre de régularisation (lambda). Il doit être > 0.
        L (np.ndarray, optional): La matrice de régularisation. Si None, la matrice identité
                                   de la bonne dimension est utilisée par défaut (régularisation de norme L2).

    Returns:
        np.ndarray: Le vecteur solution régularisé x_lambda.
    """
    if L is None:
        # Si L n'est pas spécifié, nous utilisons la matrice identité de dimension appropriée.
        # A.shape[1] est le nombre de colonnes de A, qui correspond à la dimension de x.
        L = np.eye(A.shape[1])

    # Construction des termes de l'équation normale régularisée
    ATA = A.T @ A # A_transposée * A
    ATb = A.T @ b # A_transposée * b

    # Terme de régularisation: lambda_param^2 * (L_transposée * L)
    # L'élévation au carré de lambda_param est cohérente avec la formulation mathématique standard.
    regularization_term = (lambda_param**2) * (L.T @ L)

    # La matrice du système régularisé est (A^T A + lambda^2 L^T L)
    A_reg = ATA + regularization_term

    # Résolution du système linéaire régularisé pour obtenir x_lambda
    x_lambda = np.linalg.solve(A_reg, ATb)

    return x_lambda

# --- Démonstration et Validation de la Régularisation ---
print("--- Démonstration de la Régularisation de Tikhonov ---")

# Nous réutilisons notre matrice de Hilbert mal conditionnée (A_hilbert)
# et le vecteur b_perturbe, qui a causé une solution instable.
# x_vrai est toujours le vecteur np.ones(n_hilbert).

print(f"Rappel de l'erreur sans régularisation pour b_perturbe: {diff_norm_perturb:.2e}")

# Tentons de trouver une solution stabilisée en appliquant la régularisation de Tikhonov
# sur le système A_hilbert @ x = b_perturbe.
# Nous allons tester différentes valeurs du paramètre lambda_param.

# 1. Test avec un paramètre lambda_param très petit (quasi pas de régularisation)
lambda_petit = 1e-10 # Très proche de zéro, peu d'effet régularisant
x_tikhonov_petit_lambda = tikhonov_regularization(A_hilbert, b_perturbe, lambda_petit)
diff_petit_lambda = np.linalg.norm(x_tikhonov_petit_lambda - x_vrai)
print(f"Norme de la différence (x_tikhonov - x_vrai) avec lambda_param={lambda_petit:.1e}: {diff_petit_lambda:.2e}")
assert diff_petit_lambda > diff_norm_perturb / 2, "Un très petit lambda_param devrait avoir un effet limité sur l'erreur."
print("Validation: Un petit lambda_param ne régularise pas suffisamment la solution, l'erreur reste élevée.")

# 2. Test avec un paramètre lambda_param "optimal" (trouvé empiriquement pour cette démo)
# En pratique, lambda_param serait déterminé par des méthodes plus sophistiquées.
lambda_optimal = 1e-4 # Cette valeur peut être ajustée selon n_hilbert et la perturbation
x_tikhonov_optimal_lambda = tikhonov_regularization(A_hilbert, b_perturbe, lambda_optimal)
diff_optimal_lambda = np.linalg.norm(x_tikhonov_optimal_lambda - x_vrai)
print(f"Norme de la différence (x_tikhonov - x_vrai) avec lambda_param={lambda_optimal:.1e}: {diff_optimal_lambda:.2e}")
assert diff_optimal_lambda < diff_norm_perturb / 10, "La régularisation avec un lambda_param optimal n'a pas suffisamment réduit l'erreur."
print("Validation: Le lambda_param optimal a significativement réduit l'erreur, stabilisant la solution.")


# 3. Test avec un paramètre lambda_param trop grand (sur-régularisation)
lambda_grand = 1e-1 # Une valeur excessivement grande de lambda_param
x_tikhonov_grand_lambda = tikhonov_regularization(A_hilbert, b_perturbe, lambda_grand)
diff_grand_lambda = np.linalg.norm(x_tikhonov_grand_lambda - x_vrai)
print(f"Norme de la différence (x_tikhonov - x_vrai) avec lambda_param={lambda_grand:.1e}: {diff_grand_lambda:.2e}")
assert diff_grand_lambda > diff_optimal_lambda, "Un grand lambda_param devrait augmenter l'erreur en introduisant un biais (sur-régularisation)."
print("Validation: Un grand lambda_param introduit un biais et déforme la solution, augmentant l'erreur par sur-régularisation.")

# Comparaison finale des erreurs pour illustrer l'efficacité de Tikhonov
print("\n--- Récapitulatif des Erreurs (Norme 2 de la différence avec x_vrai) ---")
print(f"1. Erreur de la solution non régularisée (x_calcule_perturbe): {diff_norm_perturb:.2e}")
print(f"2. Erreur avec Tikhonov (lambda_param={lambda_petit:.1e}): {diff_petit_lambda:.2e}")
print(f"3. Erreur avec Tikhonov (lambda_param={lambda_optimal:.1e}): {diff_optimal_lambda:.2e}")
print(f"4. Erreur avec Tikhonov (lambda_param={lambda_grand:.1e}): {diff_grand_lambda:.2e}")

# Assertion finale pour confirmer que la régularisation a amélioré la solution pour le lambda optimal.
assert diff_optimal_lambda < diff_norm_perturb, "La régularisation de Tikhonov n'a pas réussi à améliorer la solution pour le lambda_param optimal choisi."
print("Validation finale: La régularisation de Tikhonov a effectivement stabilisé la solution pour un paramètre lambda_param adéquat, réduisant significativement l'impact des perturbations initiales.")
print("--- Fin Démonstration de la Régularisation ---")
