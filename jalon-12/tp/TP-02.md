### Partie I : Fondements Théoriques de la Recherche Sémantique et la Dualité

#### 1.1 Le Principe de la Recherche Sémantique

Un moteur de recherche sémantique ne cherche pas une correspondance exacte de mots-clés. Au lieu de cela, il transforme les requêtes et les documents en représentations numériques (vecteurs). La recherche devient alors un problème de recherche des vecteurs les plus "proches" de la requête dans l'espace de plongement.

#### 1.2 Espaces de Plongement (Embeddings)

Un plongement (embedding) est une application qui mappe des éléments (mots, phrases, documents) d'un espace discret ou symbolique vers un espace vectoriel de dimension $n$ (souvent $n \gg 1$). L'idée clé est que des éléments sémantiquement similaires sont plongés à des endroits géométriquement proches dans cet espace. Par exemple, le vecteur de "roi" et le vecteur de "reine" seront plus proches que le vecteur de "roi" et le vecteur de "banane".

#### 1.3 Similarité Cosinus et sa Géométrie

Pour mesurer la "proximité" entre deux vecteurs $u$ et $v$ dans un espace euclidien, on utilise souvent la **similarité cosinus**. Elle est définie comme le cosinus de l'angle $\theta$ entre les deux vecteurs :

$$ \text{cos}(\theta) = \frac{u \cdot v}{\|u\| \|v\|} $$

où :
*   $u \cdot v$ est le produit scalaire (dot product) des vecteurs $u$ et $v$.
*   $\|u\|$ est la norme (ou magnitude) du vecteur $u$, définie par $\|u\| = \sqrt{u \cdot u}$.

La valeur de la similarité cosinus est toujours comprise entre -1 (vecteurs opposés) et 1 (vecteurs colinéaires de même direction), avec 0 indiquant des vecteurs orthogonaux (pas de similarité). Plus la valeur est proche de 1, plus les vecteurs sont considérés comme sémantiquement similaires.

**Pont Théorie-Code :** Le calcul du produit scalaire et de la norme sont les briques fondamentales à implémenter. La similarité cosinus est une simple combinaison de ces deux opérations.

#### 1.4 La Dualité en Action : Une Perspective sur la Similarité Cosinus

L'espace dual $V^*$ d'un espace vectoriel $V$ est l'espace de toutes les formes linéaires de $V$ vers le corps de base (ici $\mathbb{R}$). Une forme linéaire $f: V \to \mathbb{R}$ est une application linéaire.

Dans un espace euclidien (muni d'un produit scalaire), il existe un isomorphisme canonique entre $V$ et $V^*$. Cela signifie que pour tout vecteur $u \in V$, il existe une forme linéaire $f_u \in V^*$ telle que $f_u(v) = \langle u, v \rangle$ pour tout $v \in V$.

**Comment cela se connecte-t-il à la similarité cosinus ?**
Considérons le vecteur $u$ de notre requête. Il définit une forme linéaire $f_u$ sur l'espace des documents. La valeur $f_u(v) = \langle u, v \rangle$ représente "à quel point le document $v$ s'aligne avec la requête $u$". Lorsque nous normalisons cette expression par les normes des vecteurs, nous obtenons la similarité cosinus.
On peut interpréter la similarité cosinus comme l'application d'une forme linéaire **normalisée** (définie par le vecteur de requête normalisé $u/\|u\|$) au vecteur document normalisé $v/\|v\|$. Le résultat est une mesure de la projection orthogonale d'un vecteur normalisé sur l'autre, ce qui est précisément le cosinus de l'angle.

**Pont Théorie-Code :** Bien que vous n'implémentiez pas directement des "formes linéaires" en Python, comprendre que le produit scalaire peut être vu comme l'action d'un élément de l'espace dual sur un vecteur de l'espace original renforce la compréhension de la structure sous-jacente des opérations vectorielles.

#### 2.1 Implémentation de la Racine Carrée (Fonction Auxiliaire)

La fonction `sqrt` est essentielle pour le calcul de la norme. Puisqu'il est interdit d'utiliser `math.sqrt`, nous allons l'implémenter via la méthode de Newton-Raphson (aussi connue sous le nom de méthode babylonienne pour la racine carrée).

```python
def _sqrt_manual(x: float) -> float:
    """
    Calcule la racine carrée de x en utilisant la méthode de Newton-Raphson.
    Exclut l'utilisation de math.sqrt pour se conformer à la règle "from scratch".
    """
    if x < 0:
        raise ValueError("Cannot compute square root of negative number.")
    if x == 0:
        return 0.0

    guess = x / 2.0  # Initial guess
    tolerance = 1e-9 # Précision souhaitée

    while abs(guess * guess - x) > tolerance:
        guess = 0.5 * (guess + x / guess)
    return guess

# Assertions de validation pour _sqrt_manual
assert abs(_sqrt_manual(4.0) - 2.0) < 1e-9, "Erreur sur sqrt(4)"
assert abs(_sqrt_manual(9.0) - 3.0) < 1e-9, "Erreur sur sqrt(9)"
assert abs(_sqrt_manual(0.0) - 0.0) < 1e-9, "Erreur sur sqrt(0)"
assert abs(_sqrt_manual(2.0) - 1.414213562373095) < 1e-9, "Erreur sur sqrt(2)"
print("Toutes les assertions pour _sqrt_manual ont réussi.")
```

#### 2.2 Implémentation du Produit Scalaire (`dot_product`)

```python
def dot_product(v1: list[float], v2: list[float]) -> float:
    """
    Calcule le produit scalaire (dot product) de deux vecteurs.
    """
    assert len(v1) == len(v2), "Les vecteurs doivent avoir la même dimension pour le produit scalaire."

    result = 0.0
    for i in range(len(v1)):
        result += v1[i] * v2[i]
    return result

# Assertions de validation pour dot_product
assert dot_product([1, 2, 3], [4, 5, 6]) == 32.0, "Erreur sur dot_product simple" # 1*4 + 2*5 + 3*6 = 4 + 10 + 18 = 32
assert dot_product([0, 0, 0], [1, 2, 3]) == 0.0, "Erreur sur dot_product avec vecteur nul"
assert dot_product([1], [5]) == 5.0, "Erreur sur dot_product de dimension 1"
assert dot_product([-1, 2], [3, -4]) == -11.0, "Erreur sur dot_product avec négatifs" # -3 - 8 = -11
print("Toutes les assertions pour dot_product ont réussi.")
```

#### 2.3 Implémentation de la Norme Euclidienne (`magnitude`)

```python
def magnitude(v: list[float]) -> float:
    """
    Calcule la norme Euclidienne (magnitude) d'un vecteur.
    Utilise la fonction _sqrt_manual implémentée précédemment.
    """
    sum_of_squares = dot_product(v, v)
    return _sqrt_manual(sum_of_squares)

# Assertions de validation pour magnitude
```

#### 2.4 Implémentation de la Similarité Cosinus (`cosine_similarity`)

```python
def cosine_similarity(v1: list[float], v2: list[float]) -> float:
    """
    Calcule la similarité cosinus entre deux vecteurs.
    """
    assert len(v1) == len(v2), "Les vecteurs doivent avoir la même dimension pour la similarité cosinus."

    dp = dot_product(v1, v2)
    mag1 = magnitude(v1)
    mag2 = magnitude(v2)

    if mag1 == 0 or mag2 == 0:
        # Si un vecteur est nul, la similarité est indéfinie ou souvent considérée comme 0.
        # Ici, nous retournons 0 pour éviter la division par zéro.
        return 0.0

    return dp / (mag1 * mag2)

# Assertions de validation pour cosine_similarity
# Vecteurs identiques
assert abs(cosine_similarity([1, 2, 3], [1, 2, 3]) - 1.0) < 1e-9, "Erreur sur vecteurs identiques"
# Vecteurs opposés
assert abs(cosine_similarity([1, 2, 3], [-1, -2, -3]) - (-1.0)) < 1e-9, "Erreur sur vecteurs opposés"
# Vecteurs orthogonaux
assert abs(cosine_similarity([1, 0], [0, 1]) - 0.0) < 1e-9, "Erreur sur vecteurs orthogonaux"
# Vecteurs arbitraires
v_a = [1.0, 1.0]
v_b = [1.0, 0.0]
# cos(45 deg) = 1/sqrt(2) approx 0.7071
assert abs(cosine_similarity(v_a, v_b) - (1.0 / _sqrt_manual(2.0))) < 1e-9, "Erreur sur vecteurs à 45 deg"
# Vecteurs nuls
assert cosine_similarity([0, 0], [1, 2]) == 0.0, "Erreur sur vecteur nul"
assert cosine_similarity([0, 0], [0, 0]) == 0.0, "Erreur sur deux vecteurs nuls"
print("Toutes les assertions pour cosine_similarity ont réussi.")
```

### Partie III : Problème d'Algèbre de l'X - L'Inégalité de Cauchy-Schwarz

#### 3.1 Énoncé du Problème

```python
def verify_cauchy_schwarz(u: list[float], v: list[float]) -> bool:
    """
    Vérifie numériquement l'inégalité de Cauchy-Schwarz : |u.v| <= ||u|| ||v||.
    Retourne True si l'inégalité est vérifiée avec une certaine tolérance.
    """
    assert len(u) == len(v), "Les vecteurs doivent avoir la même dimension."

    dot_uv = dot_product(u, v)
    norm_u = magnitude(u)
    norm_v = magnitude(v)

    # Calcul des deux côtés de l'inégalité
    left_side = abs(dot_uv)
    right_side = norm_u * norm_v

    # Utilisation d'une tolérance pour la comparaison en virgule flottante
    tolerance = 1e-9

    # L'inégalité doit être vérifiée, éventuellement avec une légère marge d'erreur due aux flottants
    return left_side <= right_side + tolerance

# Vérifications de l'inégalité de Cauchy-Schwarz
# Cas 1: Vecteurs aléatoires
# Génération de vecteurs aléatoires (implémentation minimale pour éviter numpy/random)
def generate_random_vector(dim: int, seed: int = 42) -> list[float]:
    vec = []
    # Un simple LCG pour la génération pseudo-aléatoire très basique
    # Non robuste pour la cryptographie, mais suffisant ici.
    a, c, m = 1103515245, 12345, 2**31
    current_seed = seed
    for _ in range(dim):
        current_seed = (a * current_seed + c) % m
        vec.append((current_seed / m) * 20.0 - 10.0) # Scale to [-10, 10]
    return vec

# Test 2: Vecteurs colinéaires (cas d'égalité)
u_collinear = [1.0, 2.0, 3.0]
v_collinear = [2.0, 4.0, 6.0] # v = 2 * u
assert verify_cauchy_schwarz(u_collinear, v_collinear), "Cauchy-Schwarz échoue pour vecteurs colinéaires."
# Pour le cas d'égalité, on peut vérifier que la différence est minime
```
