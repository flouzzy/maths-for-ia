# TP 04 : L'échec de la réciproque (Probabilité n'implique pas presque sûre)

On code le contre-exemple de la "machine à écrire" avec les intervalles tournants.
On montre que la probabilité d'erreur à un temps n est faible, mais que chaque chemin fini toujours par faire des erreurs à l'infini (pas de convergence p.s.).

```python
import math

def intervalle_machine_a_ecrire(n):
    # Pour n>=1, trouve k tel que 2^k <= n < 2^{k+1}
    k = int(math.floor(math.log(n, 2)))
    m = n - (2**k)
    borne_inf = m / (2**k)
    borne_sup = (m + 1) / (2**k)
    return borne_inf, borne_sup

def est_dans_intervalle(omega, n):
    borne_inf, borne_sup = intervalle_machine_a_ecrire(n)
    return borne_inf <= omega < borne_sup

# On fixe un omega = 0.3
omega_fixe = 0.3
nb_erreurs = 0
# Sur 100 étapes, cet omega devrait "tomber" dans la bosse plusieurs fois.
for n in range(1, 101):
    if est_dans_intervalle(omega_fixe, n):
        nb_erreurs += 1

print("Nombre de sauts a 1 pour omega=0.3 sur 100 etapes :", nb_erreurs)
assert nb_erreurs > 3, "Il doit y avoir plusieurs pics pour un omega fixe (pas de conv p.s.)"

# En probabilité : à l'étape 64 (k=6), l'intervalle est de taille 1/64
inf, sup = intervalle_machine_a_ecrire(64)
taille = sup - inf
assert abs(taille - 1/64) < 1e-9, "L'intervalle doit etre de proba petite"
```
